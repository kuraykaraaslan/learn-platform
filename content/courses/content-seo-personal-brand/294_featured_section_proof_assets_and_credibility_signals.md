# 294. Featured Section, Proof Assets and Credibility Signals

## What It Is
The Featured section exists to reduce trust friction: a serious prospect should be able to understand the freelancer's capability in under two minutes without leaving LinkedIn, which means it needs three to five *strong* proof assets — not whatever happened to get the most likes. A well-ordered Featured section leads with a main portfolio or service page, then the best case study, then a demo video or technical walkthrough, then a lead-capture or consultation page, then a strong authority post or testimonial. Each item needs a clear, specific title rather than a vague one — "Case Study: Custom Admin Panel for Workflow Automation" does real work that "My project" does not — and each proof item should be able to answer what the problem was, what was built, what was technically difficult, what outcome it created, what the freelancer's actual responsibility was, and whether there's visible evidence, not just a claim.

Credibility signals are the broader system the Featured section is one visible piece of, and they're built through six components: clear positioning, specific proof, visible process, technical depth, consistency over time, and professional communication. Specificity does most of the heavy lifting here — "I build great software" is unfalsifiable and therefore unpersuasive, while "I build SaaS MVPs, admin panels, dashboards, API integrations and workflow automation systems for SMEs and agencies" gives a reader something concrete to evaluate and self-identify against. Showing process (discovery, scope, architecture, implementation, testing, deployment, handover) reduces a buyer's biggest hidden fear, which usually isn't "can this person code" but "will this project go well" — process visibility answers the second question directly. And showing judgment through named trade-offs ("why reduce MVP scope," "why admin panels need permissions," "why existing code needs audit before estimate") signals seniority in a way that confident-sounding absolute claims never do.

The credibility system also has a clear anti-pattern list worth memorizing: "I can build anything," cheap-pricing language, no portfolio links, an unclear headline, inconsistent posting, aggressive DMs, and exaggerated claims all actively undermine trust rather than being merely neutral. If underlying work is confidential, the Featured section and credibility posts should use the same sanitization discipline as anonymized case studies — generic but specific-sounding descriptions ("A B2B operations company needed a dashboard to replace spreadsheet-based approvals...") rather than either exposing private details or falling back to vague, unconvincing generalities.

## Key Concepts
- **Featured section as a two-minute trust test**: 3-5 strong proof assets, ordered portfolio → best case study → demo → lead-capture page → testimonial/authority post.
- **Specific titles over vague ones**: "Case Study: Custom Admin Panel for Workflow Automation" beats "My project" every time.
- **The proof-quality question set**: problem, what was built, what was technically difficult, outcome, personal responsibility, visible evidence.
- **Six credibility components**: specificity, process visibility, proof, judgment (named trade-offs), reliability signals, professional communication.
- **Specificity as the core credibility lever**: concrete service/audience claims are inherently more persuasive than broad, unfalsifiable ones.
- **Process visibility answers the real hidden question**: buyers mostly worry "will this go well," not "can this person code" — showing discovery-to-handover process addresses that directly.
- **The anti-credibility list**: "I can build anything," cheap-pricing language, no proof links, unclear headline, inconsistent posting, aggressive DMs, exaggerated claims.
- **Confidential-work sanitization**: use the same anonymization discipline as case studies — specific-sounding but non-identifying descriptions, never vague filler.

## Example Code
```md
## Featured Section Order

1. Main portfolio / service page
2. Best case study / project breakdown
3. Demo video or technical walkthrough
4. Lead capture page / consultation CTA
5. Strong authority post or testimonial

## Featured Item Title Examples

Weak:   "My project"
Strong: "Case Study: Custom Admin Panel for Workflow Automation"
Strong: "Demo: SaaS MVP Authentication, Dashboard and Admin Flow"

## Trust Phrase Library

Before estimating, I clarify...
A responsible first version should...
The hidden complexity is...
The trade-off is...
This belongs in phase two, not MVP...
A professional handover should include...
```

## When to Use
- When setting up or auditing the LinkedIn Featured section for the first time
- When a profile has proof assets scattered across posts but nothing curated for a two-minute first impression
- When writing any credibility-focused post ("how I scope projects," "what I check before estimating") and needing a structural anchor
- When deciding whether a piece of confidential work can be shown, and how to sanitize it if so
- When auditing existing content for anti-credibility signals (vague claims, inconsistent posting, aggressive pitching)

## Common Mistakes
- Featuring random posts because they received likes, rather than deliberately curated proof assets
- Using vague titles ("My project," "Recent work") instead of specific, outcome-oriented ones
- Making unfalsifiable claims ("I build great software") instead of specific, evaluable ones
- Skipping process explanation entirely and jumping straight to the finished result
- Exposing confidential client details instead of using a properly sanitized, specific-sounding description
