# 207. Pricing Psychology — Anchoring, Framing, and Option Design

## What It Is
The same accurate price, presented in a different order and structure, produces different reactions from the same client — not because the client is irrational, but because a bare number has no reference point until you give it one. Pricing psychology is the set of techniques for presenting a genuinely fair price so that its value is legible before its cost registers, rather than tricking a client into paying more than something is worth.

The core mechanism is anchoring: the first number a client sees becomes the yardstick for everything that follows. Lead with a full-scope premium option before the recommended option, and the recommended price looks reasonable by comparison; lead with nothing, or with the cheapest option first, and the client invents their own — usually lower — reference point. This is why professional proposals almost always show three tiers rather than one: a minimal option that proves you can work within tight budgets (rarely chosen, but it frames everything above it), a recommended option priced at what you actually want to deliver, and a premium option that makes the recommended tier look complete rather than stripped-down. Naming these by outcome ("Core Booking System" / "Complete Booking Platform" / "Enterprise Package") rather than by implied quality ("Basic" / "Standard" / "Premium") avoids signaling that your recommended tier is a compromise.

Sequencing matters as much as structure: price should appear only after the client has read four or five sections of their own problem being solved — context, goals, scope, process, timeline — never on page one, and never before deliverables are described. Language matters too: "investment" reframes the transaction as a return rather than a loss, and stating the price once, followed by silence, avoids the common failure of talking yourself back down by adding qualifiers after the number. None of these techniques should cross into manufactured urgency, fear-based framing, or padded scope used to justify an arbitrary number — those tactics work briefly and cost you the relationship permanently once discovered.

## Key Concepts
- **Anchoring**: presenting the highest-scope option first so the recommended price is evaluated against it, not against an uninformed low expectation.
- **Three-option structure**: Minimal / Recommended / Premium, named by outcome rather than quality tier, with the recommended option visually highlighted.
- **Decoy pricing**: a second option priced close to the target option but delivering noticeably less, making the target look like an obviously better deal — only legitimate when the decoy is a genuine scope variant, not a strawman.
- **Price sequencing**: context → goals → scope → process → timeline → price → next steps; price never appears before the value has been established.
- **"Investment" framing**: replacing "cost" with "investment" reframes the transaction as a return rather than an expense.
- **Silence after the price**: stating the number once and stopping — every additional qualifying word after the price reads as a hedge or an apology.
- **Budget-first discovery**: asking for a rough budget range before revealing your price prevents the client from anchoring on an unrealistic number first.
- **Forbidden triggers**: artificial urgency, fear-based selling, padded scope, and negotiating against yourself all produce short-term compliance and long-term distrust.

## Example Code
```markdown
## Three-Option Proposal Structure

Option A — Core Booking System (goes live fast, limited admin features): $11,000
Option B — Complete Booking Platform (recommended): $18,500  ✓ Recommended for your stage
Option C — Enterprise Package (multi-location + staff management + analytics): $28,000

[Value stack before the price:]
"To summarize what Option B covers: a fully custom booking platform,
client-facing portal with login, admin dashboard with reporting, Stripe
payment integration, email notifications, staging environment, and two
weeks of post-launch bug fixes.

The investment for this complete system is $18,500, with a 40% deposit
to begin. What questions do you have about what's included?"

[Then: stop talking.]
```

## When to Use
- Structuring any proposal where scope can genuinely be tiered into three meaningful options.
- Any time a client asks for "your best price" before naming their own budget range.
- Preparing the price section of a proposal document — decide the sequence before writing the number.
- Reviewing a draft proposal for accidental apology language or premature price placement.

## Common Mistakes
- **The proposal has one number on it, with nothing to compare it against** — Presenting a single take-it-or-leave-it price with no anchor, so the client invents their own low reference point.
- **The three tiers are labeled Basic, Standard, and Premium, right there on the proposal** — Naming tiers "Basic / Standard / Premium," which implies the recommended option is a middle-quality compromise rather than the smart choice.
- **The price is the first thing on page one, before a single sentence about the client's problem** — Putting the price on page one before any value has been described.
- **"This price expires in 48 hours" goes into the proposal, and the same number is still on offer a month later** — Using manufactured urgency ("this price expires in 48 hours") that damages trust if the price is still available afterward.
