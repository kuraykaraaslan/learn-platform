## Judging lens

FEASIBILITY — value delivered / (engineering + authoring effort) in THIS repo, with authoring cost weighted brutally because the multiplier is 412. I verified every structural claim by reading the code and running the actual markdown pipeline. Four repo facts decided most rankings: (1) adding a new `## Section` is genuinely cheap — HEADING_RULES + one LessonSections key + one LessonSectionCard call, and the card already returns null on empty html, so every new section is optional-by-construction; (2) a new section placed BEFORE `## What It Is` is silently DISCARDED, not mis-rendered, because `currentField` is null; (3) unknown fence languages do NOT throw — I ran ```predict through the pipeline and got a visible `<pre class="language-predict">`, so any YAML-widget fence MUST be extracted before markdownToHtml or raw YAML ships to the reader; (4) Mermaid is NOT wired — ```mermaid rendered as a plain code block, so the brief's "Mermaid renders natively" is false for this repo. Also verified: zustand is a declared dependency with zero imports, vitest is installed with zero test files and no config, `topbarExtra` exists unused with the comment "(e.g. search)", lesson ids are 412-unique so `#N` resolves, frontmatter is invisible to the parser today, and 609 of the 1,771 Common Mistakes bullets already carry the `- **lead** — body` shape. The decisive scoring rule: a proposal that reuses text already in the corpus beats one that authors new text 412 times, even when the new text is pedagogically better — which is why #21 dominates #1 outright. MERGES: #7 folded into #18 (same index, same sort fix, same `#N` rewriting). #6 folded into #23 (same capstone; #23's file-existence gating and separate parseCapstoneMarkdown are the buildable version). #9 (depth tiers), #31 (provenance), #32 (freshness) folded into #25 — all three are frontmatter keys plus a script, not standalone programs. #13's decision table folded into #11 (same 6-row table, minus the Mermaid dependency). #28's only cheap win — extract fences, run tsc --noEmit in CI — folded into #12/#26. DEFERRED, not scored: #3/#10 are near-duplicates of each other (symptom → probe → expect → fix); the merged version is the single largest authoring bill in the set because every probe/expect pair must be executed against a real instance for ~320 lessons — do it for the ~40 Wave-1 lessons only, as part of #27's gold set. #2 Fill the Gap is strictly downstream of #12 (you cannot blank a line in code that does not compile). #15 Prove It has no mechanism the merged #4/#21 lack. #5 Return Queue is pure code with no deck of its own — but note it becomes near-free if you run its Leitner scheduler on #21's drill outcomes instead of on newly authored items. #30 Triage is effort-S and worth doing, but delivers zero reader-facing value directly. #17 Concept Spine lost its slot because #18 already delivers its cheap 80% (the `#N` rewriting) and the remaining concepts.json layer carries the blue-soup risk. NOTE ON STATIC BUILD: there is no `output: 'export'` and `app/api/health/route.ts` exists, so this is Vercel SSG/Node, not a hard static export — client components, localStorage, prebuild scripts and generated JSON in public/ are all fine, and nothing I ranked breaks that.

### Reasoning, in ranked order

#### 9.4 — Authored Order, Vitals, and Learning Paths (merges #7 Prereq and Callback Graph)

Best ratio in the set by a wide margin, because half of it is a two-line bug fix. `getSidebarNavGroups` sorts `bracketRank(a)-bracketRank(b) || a.id-b.id` and CourseOverviewPage does `BRACKET_ORDER.filter(...).map(...)` — both verified in the source. Deleting `bracketRank` and dropping the grouping costs minutes and repairs authored sequence in 20 of 23 courses; nothing else here has that value/effort profile. Ship it alone, today. The rest decomposes cleanly by cost: `ManifestItemSchema` is a plain z.object so unknown keys are silently STRIPPED — that is the real blocker for every manifest-driven idea in this whole set, and it is a 3-line schema change. `minutes` is computed from word count, zero authoring. Absorbing #7: the `#N` link rewriter is the cheapest cross-lesson win available — ids are 412-unique (verified), so a small remark plugin turns ~127 dead refs into real links with zero content edits, and it must reuse the parser's fence tracking so it never rewrites inside code. Only the prereq edges are genuine authoring; keep the field optional, seed the ~60 spine lessons, render nothing when absent. Deduct nothing for paths.json — one hand-written file. The one flag: the sort change is visible on every course page, so it needs an explicit owner decision, not a silent merge.

#### 9 — Failure Drill

The highest value-per-authored-word proposal in the entire set, and it wins on a fact I verified: 609 of the 1,771 Common Mistakes bullets ALREADY match `- **lead** — body`, so a third of the corpus becomes predict-then-reveal with literally zero new content. The other 1,162 need a bolded lead prepended — a mechanical pass whose output is regex-verifiable, which is the only kind of AI pass that stays honest at this scale. Engineering is small and safe: `parseMistakes()` runs over the raw block after the existing split, `commonMistakes` HTML stays in place so nothing downstream breaks, and one line changes in LessonPage. This is why I reject #1: Cold Open buys the same prediction-error mechanism for 412 newly authored multiple-choice items with non-generic distractors, while this buys ~70% of it from text that already exists. Real risks are both mitigable in code: interaction friction (needs a prominent Reveal-all plus a sticky preference) and self-revealing leads (lint leads over 8 words or containing 'because/so that/which means'). Note it also hands #5 a spaced-repetition deck for free.

#### 8.5 — ⌘K Corpus Search

Zero authoring, contained engineering, and the repo is pre-shaped for it — `topbarExtra` exists unused with the comment '(e.g. search)' (verified). A prebuild script reusing CourseContentService + parseLessonMarkdown writes public/search-index.json; no new dependency needed for field-weighted token scoring. The index-size math holds: 412 records of titles + Key Concepts + Common Mistakes leads is well under 200KB raw, lazy-fetched on first open. Weighting the 1,771 mistake bullets is the correct call — it makes the corpus searchable by symptom ('double charge', 'lock timeout'), which is how a reference actually gets used. Two real flags, both cheap: LessonSectionCard takes no id today, so deep-linking to `#common-mistakes` needs an `anchorId` prop; and a stale index must fail CI via a count-equality test, because vitest is installed with zero test files and no config — someone has to write the first one. Slightly below the top two only because it improves navigation of an unverified corpus rather than improving the corpus.

#### 8.3 — content:lint — Fourteen Rules and One Waiver File

Code-only, no authoring, and it is the guardrail that makes every other mechanical pass safe to run on 412 files. Several rules pay for themselves immediately against defects I confirmed: `shape/six-sections` catches 76_rfc_process.md, whose `## Summary` / `## Alternatives Considered` are swallowed into the Example Code card by design (`matchHeading` returns null → falls through as content); `code/fence-lang` catches the 19 JSX-in-typescript fences and the 232 template-only Example sections I measured; `sources/bare-domain` is correct because I confirmed remark-gfm does NOT autolink `(zod.dev)`. The warn-then-promote staging is the right discipline for a repo with no tests. Cost is not zero — it is the violations, not the rules. One rule must be handled carefully: `voice/asserted-second-person` targets ~5% of 2,784 you/your tokens, and a blunt version would wreck the instructional voice that the voice audit explicitly says to keep. Ship that one as warn-only and probably never promote it.

#### 7.9 — Course Pack

Effort S is accurate and the value is disproportionate: two static routes per course, a @media print block, and a window.print() button. No PDF library, no backend, no authoring. It converts a URL into an artifact a buyer keeps, and the print stylesheet's `a[href^=http]::after { content: attr(href) }` quietly rescues the 150 bare-domain bullets that render as unclickable grey text on screen. The cheat sheet is the better half — forcing 13 uniform ~1029-word lessons onto three pages produces the hierarchy the corpus lacks — provided selection follows a mechanical rule (Key Concepts + mistake leads, reusing #21's parseMistakes) and never an AI re-summarisation that could invent. Flag the size honestly: the 43-lesson content-seo-personal-brand pack is ~45k words in one route; dropping hljs class markup from pack output or paginating the four largest courses handles it. Ranked below the lint gate only because it packages the corpus rather than improving or protecting it.

#### 7.7 — Six Gold Standards and a Falsifiable Rubric

Six hand-written lessons is a week of the owner's own writing and cannot be delegated — that is the entire cost, and it is the precondition that keeps 412 AI-assisted lessons from regressing to 1,030 words and one decorative fence. Authors imitate examples far more reliably than they follow specs, so this is the cheapest available defence against the exact 'reads as AI filler' failure the owner named. The rubric design is what earns the score: dimensions 1, 2 and 5 are pass/fail on artifacts (a passing tsc run, a fence inside Common Mistakes, a named ambiguous-outcome case), so a score cannot be inflated by adding prose — the failure mode of every content rubric. Keeping golds in content/_standards/ (outside content/courses/) is correct: listCourseSlugs() enumerates every directory under content/courses, so a gold folder placed there would publish itself as a course. The LLM-grader half is optional and I would defer it; the golds and the rubric doc carry nearly all the value on their own.

#### 7.4 — Broken → Fixed → Proof (absorbs #28's tsc-in-CI gate)

Highest content value in the entire set and the only proposal that fixes the corpus's most damaging verified defect — 126 of 158 TypeScript examples fail a standalone typecheck, 46 import the first owner's non-existent `@/libs/*`, and 0 of 412 files show what the code produces. Crucially it needs NO parser or type change: it restructures the inside of the existing exampleCode section using bold lead-ins, so it ships incrementally, per lesson, with no 412-file migration risk. Two sub-parts have wildly different costs and must be split. The CI gate — extract every typescript/tsx fence, run `tsc --noEmit --skipLibCheck`, allow only TS2307 — is a day of work, catches the 85 undefined-identifier lessons automatically, and makes regression impossible; do that first and independently. The full three-beat rewrite across ~175 technical lessons genuinely requires running code and is XL; stage it behind the gold lessons and the triage queue. Score is held down purely by that authoring bill; on value alone it is a 9.5. Do not attempt beat 1/beat 3 on the 232 template-only Example sections — they need a filled-in worked instance with reconciling numbers, not a compiler.

#### 7.2 — Capstone + Rubric (merges #6 Ship It)

Merged because #6 and #23 are the same proposal; #23's engineering is the buildable version and should be adopted wholesale — a separate `parseCapstoneMarkdown()` leaves the rigid six-section parser and HEADING_RULES completely untouched, which is exactly right given there is not one test protecting that parser today. Gating the route on file existence means you can ship 5 capstones instead of 23 and show nothing where there is no file, which turns an XL programme into an L one. This is the only element in the whole set that produces transfer rather than recognition — there are 0 exercises across 412 lessons — and the self-scored rubric is the only thing that punctures the felt-mastery illusion. Build the rubric rows from that course's own Common Mistakes so authoring reuses existing text. Take #6's export-packet idea (a markdown Blob download the reader can hand a manager) and drop #23's certificate route: self-issued and unverifiable, it cheapens everything around it for no engineering saving.

#### 7 — The Frontmatter Spine (absorbs #9 depth tiers, #31 provenance, #32 freshness)

I verified the central claim: the parser drops every line before the first recognized `##`, and 0 of 412 files currently have a fence before that point — so YAML frontmatter lands with a byte-identical render. The ordering discipline is non-negotiable and the proposal states it correctly: snapshot test FIRST (vitest is installed with zero test files, so this is also the repo's first test), then the parser fix, then the frontmatter. The latent bug is real — the fence branch does `buffer.push(line)` unconditionally, so one stray ``` in an intro would toggle inFence and collapse an entire lesson into one section. Generated manifests kill the second-copy-of-the-truth problem permanently. I folded in #9, #31 and #32 because all three are frontmatter keys plus a script (`depth`, `provenance`, `volatility`) and none justifies a standalone programme for a solo owner. Score held down by schema over-reach risk: every key added is a key 412 files must eventually fill, and `teaches`/`requires`/`unlocks` are 412x judgement authoring that an LLM will happily fabricate. Ship the mechanical keys now, add the graph keys per wave.

#### 6.8 — Portable Progress

Nearly free engineering: zustand@^5 is already a declared dependency with zero imports anywhere (verified), ADR 0001 §3 explicitly pre-approved localStorage progress, and there is no authoring at all. The highest-value piece is the smallest — `getLessonNeighbors` plus a footer next/prev, since every lesson is currently a terminal node and a reading session ends whenever a page ends. That piece depends on the #18 sort fix landing first, or next/prev walks the scrambled order. Hydration discipline matters: the repo already has libs/utils/isBrowser.ts and ThemeToggle as the pattern to copy, so every progress component must render a neutral skeleton until mounted. The export/import file is not optional — it is the honest answer to the ADR's own listed Loss, and losing six weeks of ticks to cleared site data would make a paid product feel cheap. Ranked here rather than higher because completion ticks measure pages turned, not knowledge — it is motivational scaffolding around an unfixed corpus, which is why it sits below the correctness and verification work.

#### 6.6 — Numbers That Matter (absorbs #13's decision table, minus Mermaid)

The cheapest possible fix for the corpus's most-cited weakness — p99 in 5 files, EXPLAIN ANALYZE in 4, zero mentions of lock_timeout — and it renders with genuinely zero UI work, which I confirmed: LessonSectionCard already styles `[&_table]`, `[&_th]`, `[&_td]` with borders. A 6-row table is fast to author AND fast to review, because each row is independently checkable, which is the only review that survives 150 lessons. The authoring rule that makes it safe is the one the proposal already states: prefer the measurement command over the stated value, since a command never goes stale, and stamp the version in the column header. I folded in #13's decision table here — same table shape, same falsifiable-signal-in-the-left-column discipline — but explicitly WITHOUT the Mermaid half, because I verified ```mermaid renders as a plain code block in this repo. Deduct for the real hazard: an unsourced derived benchmark ('SERIALIZABLE costs 15%') is worse than the adjective it replaced, so any row without either a citation link or a measurement command must be deleted rather than softened.

#### 6.2 — Jurisdiction Notes

Cheap to build, expensive to make safe — and it is the only proposal addressing content that is actively harmful rather than merely thin. Engineering is one HEADING_RULES entry and one LessonSections key for ~73 business lessons plus ~13 privacy lessons; the disclaimer relocation out of Further Reading is a mechanical edit that frees a reference slot in 40 lessons which currently have zero real links. The `### Türkiye` / `### EU` / `### US` sub-headings are safe under the existing parser precisely because unrecognized `##`/`###` lines fall through as content of the open section. What holds the score down under a feasibility lens is a dependency that is not code and cannot be scheduled: one Turkish mali müşavir pass and one lawyer pass. The name-the-publisher-not-the-rate rule is what lets these blocks survive annual revision without an annual rewrite, and it should be a lint rule, not a guideline. Settle the homepage audience line first — 'A course platform for interns and employees' versus 186 solo-operator lessons — because this section makes that contradiction impossible to ignore.
